# Relato de vulnerabilidades

Não publique vulnerabilidades, credenciais, dados pessoais ou detalhes exploráveis em Issues, Discussions ou Pull Requests públicos.

Quando o repositório oficial estiver publicado no GitHub, use **Report a vulnerability** na aba Security para enviar um GitHub Security Advisory privado. Os mantenedores devem habilitar *Private vulnerability reporting* nas configurações do repositório antes de anunciar o projeto publicamente. Se essa opção estiver indisponível, use somente um contato privado que os mantenedores tenham publicado no perfil oficial do projeto; não abra um relato público.

Inclua versões afetadas, impacto, passos mínimos para reproduzir e uma forma segura de contato. Não envie dados reais de usuários, documentos institucionais ou segredos. A equipe deve confirmar o recebimento, coordenar correção e divulgação responsável antes de publicar detalhes.

## Escopo e suporte

Enquanto o projeto não publicar uma política de versões, apenas a versão mais recente da branch principal será considerada para correções. Não há prazo de resposta ou SLA de segurança anunciado. A organização mantenedora precisa designar responsáveis e publicar uma janela de atendimento antes de oferecer suporte institucional.
